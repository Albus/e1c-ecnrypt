# Подсистема «Шифрование»

Руководство для разработчиков по использованию симметричного шифрования и управлению ключами.

Подсистема предоставляет возможность конфиденциальной обработки данных с использованием устойчивого симметричного шифрования. Ключ шифрования автоматически вычисляется на основе **уникального идентификатора (УИД)** объекта метаданных. Одна и та же операция выполняет и зашифрование, и расшифрование — повторный вызов с теми же параметрами восстанавливает исходные данные. Детали алгоритма и механизм генерации ключа полностью скрыты внутри реализации.

## 1. Состав модулей подсистемы

Подсистема включает два общих модуля с чётким разделением зон ответственности.

| Модуль | Флаги | Назначение и публичные методы |
|--------|-------|-------------------------------|
| **ШифрованиеВызовСервераПовтИсп** | `Сервер`, `Вызов сервера`, `Кэш: на время сеанса` | Клиентский интерфейс с кешированием. Передача данных только через адрес временного хранилища.<br>**Методы:**<br>• `ЕстьПравоНаШифрование()`<br>• `ОбработатьАдресВременногоХранилища(Адрес, УИД)` |
| **ШифрованиеСервер** | `Сервер` | Базовая реализация **без кеширования**. Только для серверного кода. Поддерживает `ДвоичныеДанные` и `ХранилищеЗначения`.<br>**Служебные методы:**<br>• `ОбработатьДвоичныеДанные(Данные, УИД)`<br>• `ОбработатьАдресВременногоХранилища(Адрес, УИД)` |

## 2. Публичные методы для клиентского кода

Все клиентские вызовы выполняются через модуль `ШифрованиеВызовСервераПовтИсп`. Прямая передача двоичных данных запрещена — используется временное хранилище.

### ОбработатьАдресВременногоХранилища(Адрес, УИД)

Выполняет шифрование или расшифрование данных, размещённых во временном хранилище. Результат также помещается во временное хранилище и возвращается его адрес.

#### Параметры

| Имя | Тип | Описание |
|-----|-----|----------|
| `Адрес` | Строка | Адрес временного хранилища, полученный через `ПоместитьВоВременноеХранилище`. Непустая строка, действительный адрес. |
| `УИД` | УникальныйИдентификатор | Уникальный идентификатор объекта, из которого будет сгенерирован ключ. Не может быть пустым. |

#### Возвращаемое значение

**Строка** — адрес временного хранилища с результатом операции.

#### Исключения

- «Ожидается Строка» – неверный тип адреса.
- «Ожидается не пустая Строка» – пустой адрес.
- «Ожидается адрес временного хранилища» – строка не является адресом.
- «Нет прав для чтения ключей шифрования (роль: ЧтениеКлючейШифрования)» – отсутствует роль.

#### Пример использования (клиент)

```bsl
// Исходные данные
ДвоичныеДанные = ПолучитьДвоичныеДанныеИзСтроки("Важный текст", "UTF-8");
ИсходныйАдрес = ПоместитьВоВременноеХранилище(ДвоичныеДанные);

// Уникальный идентификатор объекта
УИД = СсылкаНаОбъект.УникальныйИдентификатор();

// Шифрование
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
ЗашифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРезультата);

// Расшифровка (тот же вызов)
АдресРасшифровки = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(АдресРезультата, УИД);
РасшифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРасшифровки);
```

> ⚡ **Кеширование:** повторный вызов с теми же параметрами в рамках сеанса вернёт тот же адрес без повторной обработки.

### ЕстьПравоНаШифрование()

Проверяет наличие у текущего пользователя роли **ЧтениеКлючейШифрования**, необходимой для выполнения операций шифрования.

#### Возвращаемое значение

**Булево** — `Истина`, если роль назначена.

#### Пример

```bsl
Если ШифрованиеВызовСервераПовтИсп.ЕстьПравоНаШифрование() Тогда
    // вызов методов шифрования
КонецЕсли;
```

## 3. Методы для серверного кода

В серверном контексте доступен модуль `ШифрованиеСервер` без кеширования. При необходимости ускорения повторных вызовов можно использовать кеширующую обёртку `ШифрованиеВызовСервераПовтИсп`.

### ОбработатьДвоичныеДанные(Данные, УИД)

Шифрует или расшифровывает переданные двоичные данные. Параметр `Данные` может быть как `ДвоичныеДанные`, так и `ХранилищеЗначения` (автоматически извлекается через `.Получить()`).

#### Параметры

| Имя | Тип | Описание |
|-----|-----|----------|
| `Данные` | ДвоичныеДанные, ХранилищеЗначения | Исходные данные. Для `ХранилищеЗначения` данные извлекаются автоматически. Не может быть пустым. |
| `УИД` | УникальныйИдентификатор | Идентификатор объекта, формирующий ключ. |

#### Возвращаемое значение

**ДвоичныеДанные** — результат операции.

#### Примеры

```bsl
// Серверный код: работа с двоичными данными
Данные = ПолучитьДвоичныеДанныеИзСтроки("Секретные данные", "UTF-8");
УИД = СсылкаНаОбъект.УникальныйИдентификатор();
Результат = ШифрованиеСервер.ОбработатьДвоичныеДанные(Данные, УИД);

// Использование ХранилищеЗначения
Хранилище = Новый ХранилищеЗначения(Данные);
Результат = ШифрованиеСервер.ОбработатьДвоичныеДанные(Хранилище, УИД);
```

### ОбработатьАдресВременногоХранилища(Адрес, УИД) на сервере

Аналогичен клиентскому методу, но может вызываться напрямую через `ШифрованиеСервер`.

```bsl
АдресРезультата = ШифрованиеСервер.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
```

## 4. Схема вызова методов

```
Клиентский код (1С:Предприятие)
     │
     │  (только адрес временного хранилища + УИД)
     ▼
ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища (прокси, [Сервер, Вызов сервера, Кэш])
     │
     │  делегирует
     ▼
ШифрованиеСервер.ОбработатьАдресВременногоХранилища (базовая реализация, [Сервер])
     │
     │  извлекает данные из хранилища
     │  вызывает ОбработатьДвоичныеДанные(данные, УИД)
     │
     ▼
ШифрованиеСервер.ОбработатьДвоичныеДанные
     │
     │  при необходимости извлекает из ХранилищеЗначения
     │  генерирует ключ через внутреннюю функцию Ключ(УИД)
     │  применяет симметричное шифрование/расшифрование
     │
     ▼
Возвращает результат (ДвоичныеДанные или адрес хранилища)
```

Серверные вызовы напрямую:
```
Серверный код → ШифрованиеСервер.ОбработатьДвоичныеДанные / ОбработатьАдресВременногоХранилища
```

## 5. Логика клиент-серверного взаимодействия и кеширования

- **Клиент → Сервер**: Модуль `ШифрованиеВызовСервераПовтИсп` помечен флагом «Вызов сервера». Клиент передает только адрес временного хранилища и УИД, что полностью скрывает алгоритм шифрования.
- **Кеширование «На время сеанса»**: Модуль с суффиксом «ПовтИсп» повторно использует возвращаемые значения при одинаковых параметрах в течение жизни сеанса. Это исключает повторные криптографические вычисления. Кеш сбрасывается при завершении сеанса.
- **Модуль без кеширования** (`ШифрованиеСервер`) полезен для гарантированного выполнения без хранения состояния (отладка, собственные кеширующие обёртки).
- **Гибкость данных**: `ОбработатьДвоичныеДанные` поддерживает как `ДвоичныеДанные`, так и `ХранилищеЗначения`, что упрощает интеграцию с типовыми механизмами 1С.

## 6. Рекомендации по использованию

1. В клиентском коде всегда используйте `ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища`.
2. Перед выполнением операций шифрования проверяйте права через `ЕстьПравоНаШифрование()`.
3. На сервере для однократных или некешируемых задач вызывайте `ШифрованиеСервер`. Для ускорения повторных операций с одинаковыми параметрами — кеширующие методы.
4. Никогда не пытайтесь обращаться к методам модуля `ШифрованиеСервер` с клиента — они недоступны.
5. Не сохраняйте сгенерированные ключи в открытом виде; все операции с ключами инкапсулированы внутри подсистемы.
6. Для больших данных всегда применяйте временное хранилище, даже в серверном коде при передаче между контекстами.
