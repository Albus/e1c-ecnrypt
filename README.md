# Подсистема «Шифрование»

Руководство для разработчиков по использованию симметричного шифрования и управлению ключами.

Подсистема предоставляет возможность конфиденциальной обработки данных с использованием устойчивого симметричного шифрования.
Ключ шифрования автоматически вычисляется на основе **уникального идентификатора (УИД)** объекта метаданных.
Одна и та же операция выполняет и зашифрование, и расшифрование — повторный вызов с теми же параметрами восстанавливает исходные данные.

Детали алгоритма и механизм генерации ключа полностью **скрыты** внутри реализации. Публичный интерфейс оперирует только высокоуровневыми типами: `ДвоичныеДанные`, `УникальныйИдентификатор` и адресами временного хранилища.

## 1. Состав модулей подсистемы

Подсистема включает три общих модуля с разными флагами и особенностями кеширования.

| Модуль | Флаги | Назначение и публичные методы |
|--------|-------|-------------------------------|
| **ШифрованиеВызовСервераПовтИсп** | Сервер, Вызов сервера, Кэш сеанса | Клиентский интерфейс. Данные передаются только через временное хранилище. Кеширует результаты.<br>**Методы:**<br>• `ЕстьПравоНаШифрование()`<br>• `ОбработатьАдресВременногоХранилища(Адрес, УИД)` |
| **ШифрованиеСервер** | Сервер | Базовая реализация **без кеширования**. Доступен только в серверном коде (не вызов сервера).<br>**Служебные методы:**<br>• `ОбработатьДвоичныеДанные(Данные, УИД)`<br>• `ОбработатьАдресВременногоХранилища(Адрес, УИД)` |
| **ШифрованиеСерверПовтИсп** | Сервер, Внеш.соед., Обычн.клиент, Кэш сеанса | Кеширующий доступ к операции с двоичными данными. Доступен во внешнем соединении и обычном (толстом) клиенте.<br>**Метод:**<br>• `ОбработатьДвоичныеДанные(Данные, УИД)` |

## 2. Публичные методы для клиентского кода

Все клиентские вызовы выполняются через модуль `ШифрованиеВызовСервераПовтИсп`. Прямая передача двоичных данных запрещена — используйте временное хранилище.

Выполняет шифрование или расшифрование данных, расположенных во временном хранилище. Результат так же помещается во временное хранилище, возвращается адрес.

**Параметры**

| Имя | Тип | Описание |
|-----|-----|----------|
| `Адрес` | Строка | Адрес временного хранилища, полученный через `ПоместитьВоВременноеХранилище`. Непустая строка, действительный адрес. |
| `УИД` | УникальныйИдентификатор | Уникальный идентификатор объекта, из которого будет сгенерирован ключ. Не может быть пустым. |

**Возвращаемое значение**  
`Строка` – адрес временного хранилища с зашифрованными или расшифрованными данными.

**Исключения**

- `"Ожидается Строка"` – если `Адрес` не строка.
- `"Ожидается не пустая Строка"` – если `Адрес` пуст.
- `"Ожидается адрес временного хранилища"` – если строка не является адресом.
- `"Нет прав для чтения ключей шифрования (роль: ЧтениеКлючейШифрования)"` – отсутствует необходимая роль.

- «Ожидается Строка» – неверный тип адреса.
- «Ожидается не пустая Строка» – пустой адрес.
- «Ожидается адрес временного хранилища» – строка не является адресом.
- «Нет прав для чтения ключей шифрования (роль: ЧтениеКлючейШифрования)» – отсутствует роль.

#### Пример использования (клиент)

```bsl
// Исходные данные
ДвоичныеДанные = ПолучитьДвоичныеДанныеИзСтроки("Важный текст", "UTF-8");
ИсходныйАдрес = ПоместитьВоВременноеХранилище(ДвоичныеДанные);

// Уникальный идентификатор объекта
УИД = СсылкаНаОбъект.УникальныйИдентификатор();

// Шифрование
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
ЗашифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРезультата);

// Расшифровка (тот же вызов)
АдресРасшифровки = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(АдресРезультата, УИД);
РасшифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРасшифровки);
```

> ⚡ **Кеширование:** повторный вызов с теми же параметрами в рамках сеанса вернёт тот же адрес без повторной обработки.

### `ЕстьПравоНаШифрование()`

Проверяет наличие у текущего пользователя роли `ЧтениеКлючейШифрования`, необходимой для шифрования.

**Возвращаемое значение**  
`Булево` – `Истина`, если роль назначена.

**Пример**

#### Пример

```bsl
Если ШифрованиеВызовСервераПовтИсп.ЕстьПравоНаШифрование() Тогда
    // вызов методов шифрования
КонецЕсли;
```

## 3. Методы для серверного кода

В серверном контексте доступны как базовая реализация без кеширования, так и кеширующие обёртки.

Обрабатывает двоичные данные – шифрует или расшифровывает с ключом, сгенерированным из `УИД`.

Обрабатывает двоичные данные (шифрует или расшифровывает) с автоматической генерацией ключа из УИД.

- **Без кеширования:** `ШифрованиеСервер.ОбработатьДвоичныеДанные(...)`
- **С кешированием (на время сеанса):** `ШифрованиеСерверПовтИсп.ОбработатьДвоичныеДанные(...)`

**Параметры**

| Имя | Тип | Описание |
|-----|-----|----------|
| `Данные` | ДвоичныеДанные | Исходные данные (открытый текст или шифротекст). Не могут быть пустыми. |
| `УИД` | УникальныйИдентификатор | Идентификатор объекта, формирующий ключ. |

**Возвращаемое значение**  
`ДвоичныеДанные` – результат операции.

**Примеры**

#### Примеры

```bsl
// Серверный код без кеширования
Данные = ПолучитьДвоичныеДанныеИзСтроки("Секретные данные", "UTF-8");
УИД = СсылкаНаОбъект.УникальныйИдентификатор();
Результат = ШифрованиеСервер.ОбработатьДвоичныеДанные(Данные, УИД);

// С кешированием
РезультатКеш = ШифрованиеСерверПовтИсп.ОбработатьДвоичныеДанные(Данные, УИД);
```

### `ОбработатьАдресВременногоХранилища(Адрес, УИД)` на сервере

Аналогичен клиентскому методу, но может вызываться напрямую без дополнительного серверного вызова.

- **Без кеширования:** `ШифрованиеСервер.ОбработатьАдресВременногоХранилища(...)`
- **С кешированием:** `ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(...)`

#### Примеры

```bsl
// Без кеширования
АдресРезультата = ШифрованиеСервер.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);

// С кешированием
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
```

## 4. Логика клиент‑серверного взаимодействия и кеширования

- **Клиент → Сервер**: модуль `ШифрованиеВызовСервераПовтИсп` имеет флаг «Вызов сервера», поэтому его методы прозрачно вызываются с клиента. Передаются только адрес временного хранилища и УИД, что скрывает реализацию и минимизирует трафик.
- **Кеширование «На время сеанса»**: модули с суффиксом «ПовтИсп» повторно используют результаты для одинаковых параметров в течение сеанса. Кеш сбрасывается при завершении сеанса.
- **Модуль без кеширования** (`ШифрованиеСервер`) гарантирует выполнение операции без использования сохранённого значения. Полезен при отладке или при необходимости актуального результата.
- **Особый контекст**: `ШифрованиеСерверПовтИсп` доступен во внешнем соединении и обычном клиенте, позволяя напрямую работать с двоичными данными без временного хранилища.

## 5. Рекомендации по использованию

1. В клиентском коде всегда используйте `ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища`.
2. Перед шифрованием проверяйте права через `ЕстьПравоНаШифрование()`.
3. На сервере для частых вызовов с одинаковыми параметрами применяйте кеширующие методы.
4. Не пытайтесь вызывать методы `ШифрованиеСервер` с клиента — они недоступны.
5. Не сохраняйте ключи в открытом виде; работа с ключами скрыта внутри подсистемы.
6. Для больших данных всегда используйте временное хранилище, даже на сервере при передаче между сеансами.
