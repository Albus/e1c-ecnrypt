# Подсистема «Шифрование» — руководство для разработчиков

Подсистема предоставляет возможность симметричного шифрования данных с автоматической генерацией ключа на основе **уникального идентификатора (УИД)** объекта. Одна и та же операция выполняет и зашифрование, и расшифрование: повторный вызов с теми же параметрами восстанавливает исходные данные. Детали алгоритма и механизм генерации ключа **полностью скрыты** внутри реализации.

> **Важно:** клиентский код не должен передавать двоичные данные на сервер напрямую — необходимо использовать временное хранилище. Серверный код может работать как с временным хранилищем, так и с двоичными данными напрямую.

---

## 1. Состав модулей подсистемы

| Модуль | Флаги | Назначение и публичные методы |
|--------|-------|-------------------------------|
| **ШифрованиеВызовСервераПовтИсп** | Сервер, Вызов сервера, Кэш сеанса | Клиентский интерфейс. Данные только через адрес временного хранилища. **Методы:** `ЕстьПравоНаШифрование()`, `ОбработатьАдресВременногоХранилища(Адрес, УИД)`. |
| **ШифрованиеСервер** | Сервер | Базовая реализация **без кеширования**. Доступен только на сервере. **Служебные методы:** `ОбработатьДвоичныеДанные(Данные, УИД)`, `ОбработатьАдресВременногоХранилища(Адрес, УИД)`. |
| **ШифрованиеСерверПовтИсп** | Сервер, Внешнее соединение, Клиент (обычное приложение), Кэш сеанса | Кеширующий доступ к операции с двоичными данными. Доступен в серверном контексте, внешнем соединении и обычном (толстом) клиенте. **Метод:** `ОбработатьДвоичныеДанные(Данные, УИД)`. |

---

## 2. Публичные методы для клиентского кода

Все клиентские вызовы выполняются через модуль `ШифрованиеВызовСервераПовтИсп`.

### ОбработатьАдресВременногоХранилища(Адрес, УИД)

Выполняет шифрование или расшифрование данных, размещённых во временном хранилище. Результат также помещается во временное хранилище и возвращается его адрес.

#### Параметры

| Имя | Тип | Описание |
|-----|-----|----------|
| `Адрес` | Строка | Адрес временного хранилища, полученный через `ПоместитьВоВременноеХранилище`. Непустая строка, действительный адрес. |
| `УИД` | УникальныйИдентификатор | Уникальный идентификатор объекта, из которого генерируется ключ. Не может быть пустым. |

#### Возвращаемое значение

**Строка** — адрес временного хранилища с результатом операции.

#### Исключения

- «Ожидается Строка» — если `Адрес` не строка.
- «Ожидается не пустая Строка» — если `Адрес` пуст.
- «Ожидается адрес временного хранилища» — если строка не является адресом.
- «Нет прав для чтения ключей шифрования (роль: ЧтениеКлючейШифрования)» — при отсутствии роли.

#### Пример (клиент)

```1c
// Исходные данные
ДвоичныеДанные = ПолучитьДвоичныеДанныеИзСтроки("Важный текст", "UTF-8");
ИсходныйАдрес = ПоместитьВоВременноеХранилище(ДвоичныеДанные);

// Уникальный идентификатор объекта
УИД = СсылкаНаОбъект.УникальныйИдентификатор();

// Шифрование
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
ЗашифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРезультата);

// Расшифровка (тот же вызов)
АдресРасшифровки = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(АдресРезультата, УИД);
РасшифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРасшифровки);
```

> ⚡ **Кеширование:** повторный вызов с идентичными параметрами в рамках сеанса вернёт тот же адрес без повторной обработки.

### ЕстьПравоНаШифрование()

Проверяет наличие у текущего пользователя роли **ЧтениеКлючейШифрования**.

#### Возвращаемое значение

**Булево** — `Истина`, если роль назначена.

#### Пример

```1c
Если ШифрованиеВызовСервераПовтИсп.ЕстьПравоНаШифрование() Тогда
    // вызов методов шифрования
КонецЕсли;
```

## 3. Методы для серверного кода

В серверном коде доступны как некэшируемая базовая реализация (`ШифрованиеСервер`), так и кеширующие обёртки (`ШифрованиеСерверПовтИсп`, `ШифрованиеВызовСервераПовтИсп`). Выбор зависит от необходимости гарантированного выполнения или ускорения повторных вызовов.

### ОбработатьДвоичныеДанные(Данные, УИД)

Обрабатывает переданные двоичные данные (шифрует или расшифровывает) с автоматической генерацией ключа из УИД.

**Варианты вызова:**
- **Без кеширования:** `ШифрованиеСервер.ОбработатьДвоичныеДанные(...)`
- **С кешированием (на время сеанса):** `ШифрованиеСерверПовтИсп.ОбработатьДвоичныеДанные(...)`

#### Параметры

| Имя | Тип | Описание |
|-----|-----|----------|
| `Данные` | ДвоичныеДанные | Исходные данные (открытый текст или шифротекст). Не могут быть пустыми. |
| `УИД` | УникальныйИдентификатор | Идентификатор объекта, на основе которого формируется ключ. |

#### Возвращаемое значение

**ДвоичныеДанные** — результат операции.

#### Примеры

```1c
// Серверный код без кеширования
Данные = ПолучитьДвоичныеДанныеИзСтроки("Секретные данные", "UTF-8");
УИД = СсылкаНаОбъект.УникальныйИдентификатор();
Результат = ШифрованиеСервер.ОбработатьДвоичныеДанные(Данные, УИД);

// С кешированием (подходит для многократных вызовов с одинаковыми параметрами)
РезультатКеш = ШифрованиеСерверПовтИсп.ОбработатьДвоичныеДанные(Данные, УИД);
```

### ОбработатьАдресВременногоХранилища(Адрес, УИД) на сервере

Аналогичен клиентскому методу, но может вызываться напрямую в серверном коде без дополнительного серверного вызова.

**Варианты вызова:**
- **Без кеширования:** `ШифрованиеСервер.ОбработатьАдресВременногоХранилища(...)`
- **С кешированием:** `ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(...)`

#### Пример

```1c
// Без кеширования
АдресРезультата = ШифрованиеСервер.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);

// С кешированием
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
```

## 4. Логика клиент-серверного взаимодействия и кеширования

* **Клиент → Сервер**  
  Модуль `ШифрованиеВызовСервераПовтИсп` помечен флагом «Вызов сервера». Клиент прозрачно вызывает его методы, передавая только адрес временного хранилища и УИД. Это уменьшает объём передаваемых данных и скрывает детали шифрования.

* **Кеширование «На время сеанса»**  
  Модули с суффиксом «ПовтИсп» сохраняют результат при первом вызове с конкретными параметрами. При повторении возвращается сохранённое значение без повторных вычислений. Кеш сбрасывается в конце сеанса.

* **Модуль без кеширования (`ШифрованиеСервер`)**  
  Используется, когда требуется гарантированно выполнить операцию без использования кеша (например, отладка, сценарии с меняющимся контекстом).

* **Особый контекст доступа**  
  Модуль `ШифрованиеСерверПовтИсп` дополнительно доступен во **внешнем соединении** и **обычном (толстом) клиенте**, позволяя применять кешированную обработку двоичных данных напрямую, без временного хранилища.

---

## 5. Рекомендации по использованию

1. В клиентском коде всегда используйте `ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища`.
2. Перед выполнением операций шифрования проверяйте наличие прав через `ЕстьПравоНаШифрование()`.
3. На сервере, при частых вызовах с одинаковыми параметрами, отдавайте предпочтение кеширующим методам для повышения производительности.
4. Не пытайтесь вызывать методы модуля `ШифрованиеСервер` с клиента — они недоступны.
5. Не сохраняйте сгенерированные ключи в открытом виде; вся работа с ключами инкапсулирована внутри подсистемы.
6. Для больших объёмов данных всегда используйте временное хранилище, даже в серверном коде, если данные перемещаются между сеансами или контекстами.
