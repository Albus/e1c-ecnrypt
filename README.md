# Подсистема «Шифрование»

[![Платформа 1С](https://img.shields.io/badge/платформа-1С%208.3.27-blue)](https://v8.1c.ru/)
[![Лицензия MIT](https://img.shields.io/badge/license-MIT-green)](./LICENSE)

Симметричное шифрование данных (RC4) с автоматической генерацией ключа на основе уникального идентификатора объекта. Одна и та же операция выполняет и зашифрование, и расшифрование. Детали алгоритма и механизм ключа скрыты внутри реализации.

> **Важно:** клиентский код обязан передавать данные через временное хранилище, прямая передача двоичных данных запрещена. Серверный код может работать и с временным хранилищем, и с двоичными данными напрямую.

## Состав модулей

| Модуль | Флаги | Назначение и публичные методы |
|--------|-------|-------------------------------|
| **ШифрованиеВызовСервераПовтИсп** | Сервер, Вызов сервера, Кэш сеанса | Клиентский интерфейс с кешированием на время сеанса. **Методы:** `ЕстьПравоНаШифрование()`, `ОбработатьАдресВременногоХранилища(Адрес, УИД)` |
| **ШифрованиеСервер** | Сервер | Базовая некэшируемая реализация, доступна только на сервере. **Служебные методы:** `ОбработатьДвоичныеДанные(Данные, УИД)`, `ОбработатьАдресВременногоХранилища(Адрес, УИД)` |
| **ШифрованиеСерверПовтИсп** | Сервер, Внешнее соединение, Клиент (обычное приложение), Кэш сеанса | Кеширующий доступ к обработке двоичных данных. Доступен также во внешних соединениях и толстом клиенте. **Метод:** `ОбработатьДвоичныеДанные(Данные, УИД)` |

## Клиентские методы

Все вызовы с клиента выполняются через модуль `ШифрованиеВызовСервераПовтИсп`.

### `ОбработатьАдресВременногоХранилища(Адрес, УИД)`

Выполняет шифрование или расшифрование данных, расположенных во временном хранилище. Результат так же помещается во временное хранилище, возвращается адрес.

**Параметры**

| Имя | Тип | Описание |
|-----|-----|----------|
| `Адрес` | Строка | Адрес временного хранилища (получен через `ПоместитьВоВременноеХранилище`). Непустой действительный адрес. |
| `УИД` | УникальныйИдентификатор | Идентификатор объекта, из которого генерируется ключ. Не может быть пустым. |

**Возвращаемое значение**  
`Строка` – адрес временного хранилища с зашифрованными или расшифрованными данными.

**Исключения**

- `"Ожидается Строка"` – если `Адрес` не строка.
- `"Ожидается не пустая Строка"` – если `Адрес` пуст.
- `"Ожидается адрес временного хранилища"` – если строка не является адресом.
- `"Нет прав для чтения ключей шифрования (роль: ЧтениеКлючейШифрования)"` – отсутствует необходимая роль.

**Пример**

```1c
// Исходные данные
ДвоичныеДанные = ПолучитьДвоичныеДанныеИзСтроки("Важный текст", "UTF-8");
ИсходныйАдрес = ПоместитьВоВременноеХранилище(ДвоичныеДанные);

// Уникальный идентификатор объекта
УИД = СсылкаНаОбъект.УникальныйИдентификатор();

// Шифрование
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
ЗашифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРезультата);

// Расшифровка (тот же вызов)
АдресРасшифровки = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(АдресРезультата, УИД);
РасшифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРасшифровки);
```

> ⚡ **Кеширование:** повторный вызов с теми же параметрами в течение сеанса возвращает закешированный адрес без повторной обработки.

### `ЕстьПравоНаШифрование()`

Проверяет наличие у текущего пользователя роли `ЧтениеКлючейШифрования`, необходимой для шифрования.

**Возвращаемое значение**  
`Булево` – `Истина`, если роль назначена.

**Пример**

```1c
Если ШифрованиеВызовСервераПовтИсп.ЕстьПравоНаШифрование() Тогда
    // вызов методов шифрования
КонецЕсли;
```

## Серверные методы

В серверном коде доступны как некэшируемые, так и кеширующие варианты методов.

### `ОбработатьДвоичныеДанные(Данные, УИД)`

Обрабатывает двоичные данные – шифрует или расшифровывает с ключом, сгенерированным из `УИД`.

**Варианты вызова**

- Без кеширования: `ШифрованиеСервер.ОбработатьДвоичныеДанные(...)`
- С кешированием (на время сеанса): `ШифрованиеСерверПовтИсп.ОбработатьДвоичныеДанные(...)`

**Параметры**

| Имя | Тип | Описание |
|-----|-----|----------|
| `Данные` | ДвоичныеДанные | Исходные данные (открытый текст или шифротекст). Не могут быть пустыми. |
| `УИД` | УникальныйИдентификатор | Идентификатор объекта, формирующий ключ. |

**Возвращаемое значение**  
`ДвоичныеДанные` – результат операции.

**Примеры**

```1c
// Серверный код без кеширования
Данные = ПолучитьДвоичныеДанныеИзСтроки("Секретные данные", "UTF-8");
УИД = СсылкаНаОбъект.УникальныйИдентификатор();
Результат = ШифрованиеСервер.ОбработатьДвоичныеДанные(Данные, УИД);

// С кешированием (удобно при повторных вызовах)
РезультатКеш = ШифрованиеСерверПовтИсп.ОбработатьДвоичныеДанные(Данные, УИД);
```

### `ОбработатьАдресВременногоХранилища(Адрес, УИД)` на сервере

Аналогичен клиентскому методу, но вызывается напрямую (без серверного вызова).

**Варианты вызова**

- Без кеширования: `ШифрованиеСервер.ОбработатьАдресВременногоХранилища(...)`
- С кешированием: `ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(...)`

**Пример**

```1c
// Без кеширования
АдресРезультата = ШифрованиеСервер.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);

// С кешированием
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
```

## Архитектура клиент-серверного взаимодействия и кеширования

- **Клиент → Сервер** – Модуль `ШифрованиеВызовСервераПовтИсп` имеет флаг «Вызов сервера», поэтому его методы прозрачно доступны с клиента. Клиент передаёт только адрес временного хранилища и идентификатор, что минимизирует трафик и скрывает внутреннее устройство шифрования.
- **Кеширование на время сеанса** – Модули с суффиксом `ПовтИсп` сохраняют результат первого вызова и при повторных идентичных параметрах возвращают его без выполнения криптоопераций. Кеш живёт до завершения сеанса.
- **Некэшируемый серверный модуль** (`ШифрованиеСервер`) полезен в случаях, когда необходимо гарантированно выполнить обработку без использования кеша (отладка, динамические сценарии).
- **Расширенная доступность** – `ШифрованиеСерверПовтИсп` дополнительно работает во внешнем соединении и обычном (толстом) клиенте, позволяя напрямую обрабатывать двоичные данные без временного хранилища.

## Рекомендации по использованию

1. Клиентский код всегда обращайтесь к `ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища`.
2. Перед шифрованием проверяйте права через `ЕстьПравоНаШифрование()`.
3. На сервере, при частых вызовах с одинаковыми параметрами, используйте кеширующие версии методов для повышения производительности.
4. Не пытайтесь вызвать методы модуля `ШифрованиеСервер` с клиента — они недоступны.
5. Никогда не сохраняйте ключи в открытом виде; вся работа с ключами остаётся внутри подсистемы.
6. Для больших объёмов данных всегда применяйте временное хранилище, даже в серверном коде, если данные должны перемещаться между сеансами или контекстами.
