Подсистема «Шифрование»

Руководство для разработчиков по использованию симметричного шифрования и управлению ключами.

Подсистема предоставляет возможность конфиденциальной обработки данных с использованием устойчивого симметричного шифрования. Ключ шифрования автоматически вычисляется на основе уникального идентификатора (УИД) объекта метаданных. Одна и та же операция выполняет и зашифрование, и расшифрование — повторный вызов с теми же параметрами восстанавливает исходные данные.

Детали алгоритма и механизм генерации ключа полностью скрыты внутри реализации. Публичный интерфейс оперирует только высокоуровневыми типами: ДвоичныеДанные, УникальныйИдентификатор и адресами временного хранилища.

1. Состав модулей подсистемы

Подсистема включает три общих модуля, каждый из которых имеет свои флаги доступности и особенности кеширования.

Модуль Флаги Назначение и публичные методы
ШифрованиеВызовСервераПовтИсп Сервер Вызов сервера Кэш сеанса Предоставляет интерфейс для клиентского кода. Данные передаются только через адрес временного хранилища. Кеширует результаты на время сеанса.
Методы:
  • ЕстьПравоНаШифрование()
  • ОбработатьАдресВременногоХранилища(Адрес, УИД)
ШифрованиеСервер Сервер Содержит базовую реализацию без кеширования. Доступен исключительно в серверном контексте (не вызов сервера).
Служебные методы:
  • ОбработатьДвоичныеДанные(Данные, УИД)
  • ОбработатьАдресВременногоХранилища(Адрес, УИД)
ШифрованиеСерверПовтИсп Сервер Внеш.соед. Обычн.клиент Кэш сеанса Предоставляет кеширующий доступ к операции с двоичными данными. Доступен не только на сервере, но и во внешнем соединении и обычном (толстом) клиенте.
Метод:
  • ОбработатьДвоичныеДанные(Данные, УИД)

2. Публичные методы для клиентского кода

Все клиентские вызовы должны выполняться через модуль ШифрованиеВызовСервераПовтИсп. Прямая передача двоичных данных запрещена — используется временное хранилище.

ОбработатьАдресВременногоХранилища(Адрес, УИД)

Выполняет шифрование или расшифрование данных, размещённых во временном хранилище. Результат также помещается во временное хранилище и возвращается его адрес.

Параметры

Имя Тип Описание
Адрес Строка Адрес временного хранилища, полученный через ПоместитьВоВременноеХранилище. Непустая строка, действительный адрес.
УИД УникальныйИдентификатор Уникальный идентификатор объекта, из которого будет сгенерирован ключ. Не может быть пустым.

Возвращаемое значение

Строка — адрес временного хранилища с результатом операции.

Исключения:
  • «Ожидается Строка» – неверный тип адреса.
  • «Ожидается не пустая Строка» – пустой адрес.
  • «Ожидается адрес временного хранилища» – строка не является адресом.
  • «Нет прав для чтения ключей шифрования (роль: ЧтениеКлючейШифрования)» – отсутствует роль.

Пример использования (клиент)

// Исходные данные
ДвоичныеДанные = ПолучитьДвоичныеДанныеИзСтроки("Важный текст", "UTF-8");
ИсходныйАдрес = ПоместитьВоВременноеХранилище(ДвоичныеДанные);

// Уникальный идентификатор объекта
УИД = СсылкаНаОбъект.УникальныйИдентификатор();

// Шифрование
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);
ЗашифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРезультата);

// Расшифровка (тот же вызов)
АдресРасшифровки = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(АдресРезультата, УИД);
РасшифрованныеДанные = ПолучитьИзВременногоХранилища(АдресРасшифровки);

⚡ Кеширование: повторный вызов с теми же параметрами в рамках сеанса вернёт тот же адрес без повторной обработки.

ЕстьПравоНаШифрование()

Проверяет наличие у текущего пользователя роли ЧтениеКлючейШифрования, необходимой для выполнения операций шифрования.

Возвращаемое значение

Булево — Истина, если роль назначена.

Пример

Если ШифрованиеВызовСервераПовтИсп.ЕстьПравоНаШифрование() Тогда
    // вызов методов шифрования
КонецЕсли;

3. Методы для серверного кода

В серверном контексте доступны как некэшируемая базовая реализация, так и кеширующие обёртки. Выбор зависит от необходимости гарантированного выполнения или ускорения повторных вызовов.

ОбработатьДвоичныеДанные(Данные, УИД)

Обрабатывает переданные двоичные данные (шифрует или расшифровывает) с автоматической генерацией ключа из УИД.

Без кеширования: ШифрованиеСервер.ОбработатьДвоичныеДанные(...)

С кешированием (на время сеанса): ШифрованиеСерверПовтИсп.ОбработатьДвоичныеДанные(...)

Параметры

Имя Тип Описание
Данные ДвоичныеДанные Исходные данные (открытый текст или шифротекст). Не могут быть пустыми.
УИД УникальныйИдентификатор Идентификатор объекта, на основе которого формируется ключ.

Возвращаемое значение

ДвоичныеДанные — результат операции.

Примеры

// Серверный код без кеширования
Данные = ПолучитьДвоичныеДанныеИзСтроки("Секретные данные", "UTF-8");
УИД = СсылкаНаОбъект.УникальныйИдентификатор();
Результат = ШифрованиеСервер.ОбработатьДвоичныеДанные(Данные, УИД);

// С кешированием (подходит для многократных вызовов с одинаковыми параметрами)
РезультатКеш = ШифрованиеСерверПовтИсп.ОбработатьДвоичныеДанные(Данные, УИД);

ОбработатьАдресВременногоХранилища(Адрес, УИД) на сервере

Аналогичен клиентскому методу, но может вызываться напрямую в серверном коде без дополнительного серверного вызова. Доступен как с кешированием, так и без.

Без кеширования: ШифрованиеСервер.ОбработатьАдресВременногоХранилища(...)

С кешированием: ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(...)

// Без кеширования
АдресРезультата = ШифрованиеСервер.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);

// С кешированием
АдресРезультата = ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища(ИсходныйАдрес, УИД);

4. Логика клиент-серверного взаимодействия и кеширования

  • → Клиент → Сервер: Модуль ШифрованиеВызовСервераПовтИсп имеет флаг «Вызов сервера», поэтому его экспортные методы прозрачно вызываются с клиента. Клиент передаёт только адрес временного хранилища и уникальный идентификатор, что минимизирует объём передаваемых данных и скрывает реализацию шифрования.
  • ⏱ Кеширование «На время сеанса»: Модули с суффиксом «ПовтИсп» повторно используют возвращаемые значения при идентичных параметрах в течение жизни сеанса. Это ускоряет работу, так как исключает повторные криптографические вычисления. Кеш автоматически сбрасывается при завершении сеанса.
  • ✖ Модуль без кеширования (ШифрованиеСервер): Полезен, когда необходимо гарантированно выполнить операцию без использования сохранённого значения (например, при отладке или в сценариях с изменяющимся контекстом).
  • ● Особый контекст доступа: Модуль ШифрованиеСерверПовтИсп дополнительно доступен во внешнем соединении и обычном (толстом) клиенте, что позволяет использовать кешированную обработку двоичных данных напрямую в этих режимах, не прибегая к временному хранилищу.

5. Рекомендации по использованию

  1. В клиентском коде всегда используйте ШифрованиеВызовСервераПовтИсп.ОбработатьАдресВременногоХранилища.
  2. Перед выполнением операций шифрования проверяйте наличие прав через ЕстьПравоНаШифрование().
  3. На сервере, если предполагаются частые вызовы с одинаковыми параметрами (например, в цикле), отдавайте предпочтение кеширующим методам для повышения производительности.
  4. Никогда не пытайтесь обращаться к методам модуля ШифрованиеСервер с клиента — они недоступны.
  5. Не сохраняйте сгенерированные ключи в открытом виде; все операции с ключами инкапсулированы внутри подсистемы.
  6. Для больших данных всегда применяйте временное хранилище — это справедливо и для серверного кода, если данные перемещаются между сеансами или контекстами.
